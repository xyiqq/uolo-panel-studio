# PDF 全页面审计与二维码接口

日期：2026-09-22。项目：uolo-panel-studio。

## 用户需求与实际范围

统一 PDF 排版，让非专业读者也能找到用途、位置和待办事项；物料清单不自动填写建模设备参数；解决纯文本二维码在微信中的使用问题。用户进一步明确：未来另建按项目组织的网页，本次只保留接入接口，不建设或部署网页服务。保留此前取消旧方案迁移和交付流程相关修改。

## 根因及修复

1. **纸张设置冲突**：不同文档声明横向、纵向和小尺寸纸张，且 `app.css` 还有全局横向 `@page`。仅修改预览不能修复实际 PDF。统一为 A4 竖向，实际测得每页约 595 × 842 pt；铭牌保留 90 × 60 mm 裁剪区域，放在 A4 内。
2. **缺少内容分页**：固定纸张容器无法容纳长表格。新增浏览器测量分页，逐行分表、续页重复表头、保留标签分组，页脚按所选页面重新编号。修复号码管标题被整组重复、检查单交互控件与打印文字导致页数不同的问题。
3. **阅读对象不明确**：各表新增中文阅读说明、空状态和状态解释，专业数值保留单位；封面提示不同阅读目的的查阅顺序。
4. **建模资料被误当采购资料**：PDF 和 CSV 共用中性物料清单，移除品牌、型号、额定参数、参考价与产品备注。保留通用类别、数量、单位、编号及安装位置。内部选型和计算数据未删除。
5. **线材同名重复**：规格隐藏后，原先分规格行无法区分，现按用途汇总；明确出箱芯线米数不等于成品多芯电缆采购米数。
6. **二维码内容类型不合适**：移除纯文本回退，改为外部 HTTPS 项目页链接；未配置时不生成二维码。有关微信文本码限制的背景参考：[草料说明](https://cli.im/help/operation-tutorials/qr-code-we-chat2)。

## 后续项目网页接口约定

每份方案独立保存 `qrProjectUrl`。在文档设置选择“打开项目网页（HTTPS）”后才启用，开关字段为 `labelRules.qrMode = "online"`。

```json
{
  "qrProjectUrl": "https://your-domain.example/projects/project-a",
  "labelRules": { "qrMode": "online" }
}
```

- 项目／箱体二维码：直接使用项目网址。
- 回路二维码：在项目网址上设置查询参数 `c`，如 `?c=C01`；已有其他查询参数保留，回路编号按 URL 规则编码。
- 后续网页按项目路径读取资料，再根据 `c` 定位回路；不依赖本机浏览器存储。
- 未配置、旧纯文本模式、本机地址或不合法网址均不生成二维码。旧 `publicBaseUrl` 不会自动作为新项目页使用。
- 当前仅提供配置与链接生成，不上传资料、不创建网页、不检查公网可达性。正式网址上线后仍须用手机微信实扫验收，推荐稳定、简短的项目网址。

## 验证与证据

- `npm test`：48 个文件、278 项测试通过，覆盖交付流程、参数隐藏、数量汇总、二维码接口、内容保留和标签尺寸。
- `npm run build`：最终构建通过。
- `node scripts/audit-pdf-export.mjs`：Chrome 实际导出空白方案 16 页、44 回路完整方案 78 页、含交换机／继电器／端子的方案 30 页，共 124 页。逐页验证 A4 竖向、预览和打印页数一致、无布局溢出及脚本异常。
- 使用 Poppler 渲染全部页面检查布局，并放大复查物料清单；修复前实际 PDF 曾出现横向拆页，修复后消失。
- Edge 额外验证 A4 30 格、48 格、自定义标签纸，各选定一张输出为一页 A4 竖向；仅选封面时页码为“第 1 / 1 页”。
- 独立复核：160 行长短中文表格分页为 9 页，行数完整、没有重复，表头及页脚保留。
- `git diff --check`：无空白错误；现有 LF/CRLF 提示为 Git 换行转换提示。

审计脚本与中间 PDF 位于 `scripts/audit-pdf-export.mjs`、`.playwright-cli/pdf-audit/`。供查看的样张为 `output/pdf/网络与照明控制-交付排版样张.pdf`；其中 example.com 二维码仅用于排版测试，不是已上线的项目网站。
