## 3. 智能模块品牌方案（用户确定：Crestron、KNX、涂鸦 DIN、Lutron、明纬 DIN 电源、DALI 电源）

### 3.1 对数据模型的共同影响

这六类中四类是**专用总线系统**，因此 schema v3 必须新增“总线（bus）”概念，而不只是新增 kind：

```
design.buses = [{
  id:"BUS-KNX-1", type:"knx"|"cresnet"|"qslink"|"dali"|"rs485"|"0-10v",
  psuIds:[…], deviceIds:[…],
  voltage, budget:{ unit:"mA"|"W", capacity, used }, maxDevices, maxLength
}]
```

| 总线 | 电压/类型 | 供电与预算 | 关键限制（审计） | 布线类 |
|---|---|---|---|---|
| KNX TP1 | 30 V DC SELV | KNX 电源 640 mA（如 MDT STC-0640、明纬 KNX-20E-640） | 一条线 ≤ 64 设备；总线电流 ≤ 电源 | `comms/SELV`，需与 230 V 隔离 |
| Cresnet | 24 V DC + 数据 4 线 | DIN-PWS50（按 W 预算） | 设备功耗之和 ≤ 电源 W | `comms/SELV` |
| Lutron QS Link | 4 线，24 V DC | QS 电源/处理器供电（按 PDU 预算） | PDU 之和 ≤ 供电能力 | `comms/SELV` |
| DALI / DALI-2 | 16 V 2 线，非 SELV（基本绝缘） | DALI 总线电源 ≤ 250 mA（明纬 DLP-04R、Lunatone、Tridonic） | 64 地址/线；总线电流 ≤ 250 mA；线长 ≤ 300 m | `comms/FELV`，可与 230 V 同管但须 300/500 V 级电缆 |
| Modbus RS485（涂鸦/电表） | 差分 | 无 | 终端电阻、A/B 极性待核 | `comms` |
| Zigbee / Wi-Fi（涂鸦 DIN） | 无线 | 仅取电 L/N | 箱体为金属外壳时信号衰减提示（pending） | 仅 `power` |

新增审计码：`BUS_BUDGET`、`BUS_DEVICE_LIMIT`、`BUS_SELV_SEGREGATION`、`DALI_BUS_CURRENT`、`WIRELESS_IN_METAL_BOX`、`MODULE_FEED`（多路模块的馈电方式：共用馈电 vs 每路独立馈电，由断路器 In 与模块每路额定值共同校核）。

| 品牌 | 型号族 | kind | 建模要点 |
|---|---|---|---|

| Lutron HomeWorks QS/QSX | LQSE-4A5-D（4 路自适应调光）、LQSE-4T10-D / LQSE-4S10-D（4 路开关/继电器）、LQSE-2DAL-D（DALI）、LQSE-4M-D（电机）、QS Link 电源、HQP7 处理器 | `dimmer / relay / gateway / psu` | QS Link；调光模块对负载类型（LED/白炽/低压）有相位/负载表，标 pending |

### 3.3 回路器件链的最终形态

```
circuit.devices = [
  { role:"protection", productId },               // MCB/RCBO/智能断路器（必需）
  { role:"rcd", productId },                      // RCCB（可选）
  { role:"control", moduleId:"K1", channel:2 },   // 指向 design.modules 中的共享多路模块
  { role:"meter", productId | moduleId }
]
design.modules = [{ id:"K1", productId, busId, channels:{1:"C01",2:"C19"}, feed:"shared"|"perChannel", feedCircuit:"C-SMART" }]
```

自动建议一条 `C-SMART 智控电源回路`（给网关/处理器/电源供电），由用户确认后加入。

## 4. 标签功能方案（用户打印机：Brother PT-D210）

### 4.1 关键事实

- **PT-D210 是独立手持机，无 USB / 蓝牙 / 电脑接口**，软件无法直接驱动它打印；TZe 色带 3.5–12 mm；机身不支持二维码。
- 因此“系统内的标签功能”必须以**生成物**为核心，而不是驱动打印机：

| 输出 | 载体 | 适用 | 二维码 |
|---|---|---|---|
| A4 不干胶 PDF（一期主力） | 办公激光/喷墨打印机 | 箱门回路总表、箱体铭牌、电缆挂牌、端子排条 | 支持 |
| PT-D210 人工录入清单 | 屏幕/打印页，每条 ≤ 12 mm 高度对应字数 | 断路器面标（如 `C01 公区照明 16A`）、号码管 | 不支持 |
| P-touch Editor CSV（数据库导入） | 如后续升级 PT-P710BT / PT-P900W / PT-E550W | 面标 + 二维码 + 线缆缠绕/旗标模板 | 支持（24 mm 色带） |
| 每枚 PNG | 任意 App | 精臣/硕方等手机 App 手动导入 | 支持 |
| Web Bluetooth 直连（可选二期） | 精臣 B1/B21（`niimbluelib`，MIT） | 浏览器内直接出标签 | 支持 |

### 4.2 标签类型与内容

1. **断路器面标**：`回路号 · 名称 · In/漏保`，按 18 mm 模位宽自动分单模/双模。
2. **箱门回路总表**：表格卡（回路、名称、房间、开关规格、相位），A4/A5 不干胶。
3. **端子/号码管**：`C01-L1`、`X1:12`，两端同号；来源为现有 `wires`（端子 ID 已唯一）映射到施工编号。
4. **电缆挂牌**：出箱电缆 `C01 3×2.5 Cu/PVC → 公区照明`。
5. **箱体铭牌**：方案名、版本、日期、签认状态 + **方案二维码**。

### 4.3 二维码内容（两种模式，方案设置中切换）

- 离线模式（当前单 HTML）：紧凑文本 `PDX1|方案名|C01|公区照明|iDPN N Vigi C10|30mA|L1`，扫码即读。
- 在线模式（Docker 部署后）：`https://<host>/d/<designId>?c=C01`，打开即定位回路；`designId` 在 v3 schema 中作为方案字段预留。
- 库：`qrcode`（MIT）。

### 4.4 硬件建议（仅建议，不强制）

若希望面标也带二维码并由系统直接出片：Brother **PT-P710BT**（USB/蓝牙，24 mm，P-touch Editor 支持 CSV 与二维码）或工业型 **PT-E550W**（线缆缠绕/旗标模板）。预算优先可选精臣 B21（可走 Web Bluetooth 直连）。

## 5. 系统图导出（用户：PDF 优先，SVG 可接受）

- 一期：SVG 生成器 + **浏览器打印生成 PDF**（`@page A3 landscape`，系统字体，矢量，零依赖）。项目已有 `@media print` 基础。
- 二期：`jspdf + svg2pdf.js` 直接生成 PDF 文件。注意 **中文需内嵌字体子集**（思源黑体/Noto Sans SC 子集约 2–4 MB），单文件体积会明显增加；建议在 Docker 阶段改为服务端（无头 Chromium）出 PDF，浏览器端保留打印路线。
- SVG 始终可直接下载。

## 6. 交付形态（用户：先单 HTML，后 Docker）

现在就要做的架构预留（不实现服务端）：

1. `storage` 适配层接口：`load/save/list/export`，当前实现 `localStorage + 文件`；Docker 阶段增加 REST 实现，UI 不改。
2. 方案字段新增 `designId`（UUID）、`revision`、`updatedAt`，供二维码 URL 与服务端存储使用。
3. 图片与字体资源走构建时内联（`vite-plugin-singlefile`），Docker 阶段同一份构建可直接由 nginx 静态托管。
4. Docker 阶段方案（后续）：`nginx` 托管静态 + 轻量 API（Node/Hono 或 Go）存 JSON 到卷；可选无头 Chromium 出 PDF。
